# Portfolio: full-stack personal site with an admin dashboard

React + Vite + TypeScript (public site and admin) · Spring Boot 4 / Java 17 (API) · PostgreSQL · nginx · Docker.

```
 visitor ──HTTPS──► Caddy (optional, automatic certificates)
                      │
                      ▼
                    nginx ── serves the React app, adds security headers and SEO tags
                      │  /api/*
                      ▼
                  Spring Boot ──► PostgreSQL        (uploaded images live in a Docker volume)
```
Only one port is ever public. The database and the API are not reachable from outside Docker.

## 1. Try it on your computer

You need [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or Docker Engine + the Compose plugin).

**Before you start:** stop anything from the development setup that uses port 8080 (the `mvn spring-boot:run` window, `npm run dev`). The old `portfolio-db` container can stay, or remove it with `docker rm -f portfolio-db`.

```bash
cd path/to/this/folder           # the one containing docker-compose.yml
./scripts/init-env.sh local      # creates .env with generated secrets
```
Open `.env` and replace the two `TODO_REPLACE` lines:

```
ADMIN_EMAIL=you@example.com
ADMIN_PASSWORD='at-least-12-characters'     # single quotes if it contains $ or #
```
Then:
```bash
docker compose up -d --build     # first build takes several minutes
docker compose ps                # wait until db, backend and frontend say "healthy"
```
Open **http://localhost:8080** (site) and **http://localhost:8080/admin** (dashboard).

> Your local development data (projects, photo) is not copied into this stack. It starts empty except for your
> name, headline and skills. Add your content again in the admin, which only takes a few minutes.

## 2. Put it on the internet (a server with a domain)

You need: a Linux server (Ubuntu 22.04/24.04, **2 GB RAM or more**), a domain name, and about 30 minutes.

1. **Install Docker** on the server: <https://docs.docker.com/engine/install/ubuntu/>
2. **Point your domain at the server:** create an `A` record `example.com → <server IP>` at your domain registrar.
3. **Open only the web ports** in the firewall (Docker publishes the ports itself, so ufw is a second layer):
   `sudo ufw allow OpenSSH && sudo ufw allow 80,443/tcp && sudo ufw allow 443/udp && sudo ufw enable`
4. **Copy this folder to the server** (`git clone`, or `rsync -av --exclude node_modules --exclude target ./ user@server:portfolio/`).
5. On the server, inside the folder:
   ```bash
   ./scripts/init-env.sh production example.com     # your real domain
   nano .env                                        # set ADMIN_EMAIL and ADMIN_PASSWORD
   docker compose --profile https up -d --build
   ```
6. Wait a minute, then open **https://example.com**. Caddy gets the HTTPS certificate by itself.
7. Log in at `/admin`, add your content, **then delete the `ADMIN_PASSWORD=` line from `.env`** and run
   `docker compose up -d --force-recreate backend`. The account already exists in the database, so the password
   no longer needs to sit in a file.
8. **Backups** (see section 4): run `./scripts/backup.sh` once to confirm it works, then schedule it daily.
9. Tell Google about the site: add it in Search Console and submit `https://example.com/sitemap.xml`.

**Other hosts** (Render, Railway, Fly.io, a company load balancer): skip `--profile https`; the platform provides HTTPS.
Set `HTTP_BIND=0.0.0.0` so the platform can reach nginx, make sure `SITE_BASE_URL` is your public https address, and
add the platform's proxy address range to the `geo $realip_remote_addr` block in `frontend/nginx/default.conf` so nginx
trusts its `X-Forwarded-*` headers. The Compose file itself is the tested path; platform-specific setup is yours to verify.

## 3. Settings (`.env`)

| Variable | Needed | What it does |
|---|---|---|
| `POSTGRES_PASSWORD` | yes | Database password. Generated by `init-env.sh`. |
| `IP_HASH_SECRET` | yes | Secret key used to hash visitor IPs (they are never stored raw). 32+ random characters. |
| `SITE_BASE_URL` | yes | Your public address. Used for canonical links, social previews and the sitemap. |
| `DOMAIN` | for HTTPS | Your domain, used by Caddy. |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | first start | Creates the first admin if none exists. Password: at least 12 characters. |
| `SESSION_COOKIE_SECURE` | no | `true` (default) for real sites. `false` only to try the stack on plain `http://localhost`. |
| `HTTP_BIND`, `HTTP_PORT` | no | Where nginx listens on the host. Default `127.0.0.1:8080`. |

`.env` holds secrets: it is in `.gitignore`. Never commit it or paste it into chats or issues.

## 4. Everyday commands

```bash
docker compose ps                         # status and health
docker compose logs -f backend            # live backend log (Ctrl+C to stop watching)
docker compose up -d --build              # deploy changes after you edit code or pull updates
docker compose stop / start               # pause and resume; data is kept
./scripts/backup.sh                       # database + images -> ./backups/
./scripts/restore.sh backups/db_X.sql.gz backups/uploads_X.tar.gz     # REPLACES current data
```
**Backups:** `backup.sh` writes into `./backups` on the same machine. Copy them somewhere else too (another server, cloud
storage). A backup on the same disk does not survive losing the disk. Example daily schedule (`crontab -e`):
`0 3 * * * cd /home/you/portfolio && ./scripts/backup.sh >> backups/backup.log 2>&1`

**Forgot the admin password** (there is no reset screen yet):
```bash
docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "DELETE FROM admin_user;"'
# put the new ADMIN_EMAIL / ADMIN_PASSWORD in .env, then:
docker compose up -d --force-recreate backend
```
**Never run** `docker compose down -v`: the `-v` deletes your database and images.

## 5. What is protected, and what is up to you

Built in: HTTPS with HSTS; a strict Content-Security-Policy (no inline scripts); `HttpOnly` + `SameSite=Strict` session
cookie; CSRF tokens; login lockout and per-IP rate limits; contact-form honeypot; upload checks by file content; SSRF-safe
link checker; database and API unreachable from outside; containers run as non-root with a read-only filesystem and no
extra privileges; secrets only in `.env`.

Up to you: a strong, unique admin password; keeping the server updated (`sudo apt update && sudo apt upgrade`);
off-server backups; rebuilding images now and then (`docker compose pull && docker compose up -d --build`) to pick up
security fixes in the base images; running the test suites before you deploy (section 7).

## 6. Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| `docker compose up` says a variable is required | A value is missing from `.env`. The message names it. |
| `backend` keeps restarting | `docker compose logs backend`. Common: `ADMIN_PASSWORD must be at least 12 characters`; wrong database password after changing `POSTGRES_PASSWORD` on an existing volume (the old password is stored in the volume). |
| Site loads but data says "couldn't load" | Backend not healthy yet: `docker compose ps`, then the backend log. |
| Can't log in on `http://localhost` | Set `SESSION_COOKIE_SECURE=false` in `.env`, then `docker compose up -d --force-recreate backend`. Never use `false` on a real site. |
| Blank page, errors in the browser console mentioning "Content Security Policy" | A resource is blocked by the policy in `frontend/nginx/security-headers.conf`. Tell me the exact console message. |
| `bind: address already in use` | Another program uses port 8080. Set `HTTP_PORT=8090` in `.env`. |
| HTTPS certificate not issued | The domain must already point at the server, and ports 80/443 must be open. `docker compose logs caddy`. |
| Backend fails with a read-only filesystem error | Remove the `read_only: true` and `tmpfs` lines of the `backend` service, rebuild, and tell me the error. |
| Social previews show old text | They cache. Re-scrape with the platform's debugger (Facebook Sharing Debugger, LinkedIn Post Inspector). |

Check the SEO tags that crawlers see (no JavaScript): `curl -s https://example.com/projects/your-slug | grep -iE "og:title|<title"`.

## 7. Development and tests

```
backend/    Spring Boot API       mvn verify          (needs Docker for the integration tests)
frontend/   React app + admin     npm install && npm test && npm run build
```
Day-to-day development without Docker for the app itself: start PostgreSQL, run the backend with
`SPRING_PROFILES_ACTIVE=dev mvn spring-boot:run` and the frontend with `npm run dev` (details in each folder's README).
Run both test suites before every deploy.
